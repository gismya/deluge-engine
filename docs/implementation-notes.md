# Implementation notes

Traps hit while building deluge-engine: what happened, where, and how to avoid it. The spikes' traps are in [spike-findings.md](spike-findings.md) ("Tooling problems" and the tables above it), [perform-findings.md](perform-findings.md) and [setup-findings.md](setup-findings.md).

## E1: the build

- **Compile in place works with the prefix header.** `engine/platform/host_prefix.h` is force-included first and includes the generated `RZA1/cpu_specific.h`, so the firmware's own copy, which `src/definitions.h` finds as a sibling before any `-I`, hits its include guard and is a no-op. Neither fallback (`-ivfsoverlay`, a seam) was needed. ninja's dependency log still shows the firmware's `cpu_specific.h` opened by about 420 TUs: that's the guarded no-op. `-Werror=macro-redefined` would fail the build if its body were ever read. The generated `iodefine` headers win by being first on the include path. `check.py` fails if any TU reads the firmware's own `RZA1/system/iodefine*.h`.
- **The firmware's global destructors must not run.** The Deluge never exits. At exit, `FileReader::~FileReader` frees `fileClusterBuffer`, which points `CACHE_LINE_SIZE` past the block it allocated, and malloc aborts. Host front ends end with `std::_Exit()` after flushing, as `engine/cli/render_preset.cpp` does.
- **UBSan exemptions are per file and per check** (`engine/platform/ubsan_ignorelist.txt`, passed with `-fsanitize-ignorelist`). Every other check stays on everywhere, with `-fno-sanitize-recover`. Each entry is a place where the firmware relies on what both the Deluge's Cortex-A9 and arm64 do:
  - `dsp/reverb/freeverb/freeverb.cpp`, `float-cast-overflow`: `Freeverb::update` (line 90 on) converts `INT32_MAX`-scaled floats to `int32`; `(float)INT32_MAX` is 2^31, out of range. `vcvt` and `fcvtzs` both saturate.
  - `fatfs/ff.c`, `alignment`: `ld_word` (line 617) and its siblings load through `WORD*`/`DWORD*` at any byte offset of a sector buffer. Both CPUs allow unaligned plain loads.
  - `modulation/automation/auto_param.cpp`, `alignment`: line 2097 compares an XML value's first two chars with "0x" through a `uint16_t*`.
  - Likely next, same pattern, not exempt until one fires: the other `*(uint16_t*)`/`*(uint32_t*)` compares with `charsToIntegerConstant` in `audio_file.cpp`, `note_row.cpp`, `output.cpp`, `song.cpp` and `instrument_clip_view.cpp`. Add each when it fires, with its line, here and in the ignorelist.
- **The output dither differs per channel.** A mono preset's L and R aren't sample-equal (±256 in the low bits). Compare levels, not samples.
- **`newfs_msdos` and a plain file.** It has no `-C` (create an image), so make a sparse file of the size first. macOS 27 formats the plain file given an explicit geometry: `newfs_msdos -F 32 -c 64 -S 512 -s SECTORS -h 255 -u 63 -o 0 FILE`. macOS 26 (the CI runner) refuses even with `-o 0`: "Inappropriate ioctl for device … Cannot get partition offset". There, attach the file as a raw disk with no mount, format the device, then detach: `hdiutil attach -imagekey diskimage-class=CRawDiskImage -nomount FILE` gives `/dev/diskN`; then `newfs_msdos -F 32 -c 64 -v DELUGE /dev/rdiskN` and `hdiutil detach /dev/diskN`. That route works on macOS 27 too, where `hdiutil` warns it is deprecated in favour of `diskutil image attach --noMount`, which macOS 26 may not have. The smoke test tries the plain file first and falls back to the device (`tests/smoke/test_render_pack.py`); E3's card image builder will meet the same thing. FAT32 with 32 KiB clusters needs at least 65525 clusters, so the image is at least about 2.1 GB, sparse (4 MB on disk for one preset). The firmware's `scripts/generative/fat_image.py` then writes files onto it with no mount.
- **`pack/` isn't all CC0.** `pack/LICENSES.md` has a "Derived from the factory presets" section with no CC0 claim. Tests use only presets under "Generated files" (the smoke test uses `GEN Sine Sub`).
- **cmake isn't on PATH on the build Mac.** `check.py` falls back to the firmware's dbt toolchain (`~/source/deluge-generative/toolchain/current/{cmake,ninja-build}/bin`).
- **CMake regex alternation takes the first match, not the longest.** `\.(c|cpp)` matched `foo.c` in `foo.cpp`. Put the longer alternative first.
- **The firmware needs Apple clang 21 or newer.** `util/container/enum_to_string_map.hpp:23` static_asserts on `std::size()` of a reference parameter, which only compiles with P2280 (unknown references in constant expressions). Apple clang 21.0.0 (Xcode 26.6 and 27.x) builds it. Apple clang 17.0.0 (Xcode 16.4, the macos-15 runner's default) fails in `gui/ui/ui.cpp:494`. `CMakeLists.txt` probes the construct at configure time and stops with a message naming the minimum. CI runs on the macos-26 image with Xcode 26.6 selected by path, and checks that Xcode 26.0.1's older clang trips the probe.

## E2: platform layer and the `long` audit

### Platform traps
- **`cvEngine.init()` hangs on the host.** `deluge_main()` calls `cvEngine.init()` (`processing/engines/cv_engine.cpp:63`), which calls `delayMS(10)` — a busy-wait on `*TCNT[TIMER_SYSTEM_SLOW]` in host register RAM that never ticks. `bootFirmware()` (`engine/platform/host_startup.cpp`) intentionally skips `cvEngine.init()` (as `perform_engine.cpp` did).
- **Firmware `printf.h` redefines `snprintf` as a macro.** Any host file that transitively includes `io/debug/log.h` (e.g., via `model/song/song.h`) gets `#define snprintf snprintf_` from `firmware/src/lib/printf.h`, breaking `std::snprintf`. Call unqualified `snprintf` (or include host-only helpers separately).
- **Eviction re-entrancy and sibling destruction in `host_gma.cpp`.** Calling `Stealable::steal()` can destroy other queued `Stealable` nodes in the same list (e.g., `WaveTableBandData::steal()` deletes its `WaveTable` and every sibling `WaveTableBandData`). The eviction loop unlinks the node first, runs `steal()` + `~Stealable()` + `dealloc()`, and restarts scanning the queue from `getFirst()`, marking skipped (`!mayBeStolen`) nodes with a per-pass traversal ID. A dedicated `gEvicting` guard prevents re-entrant eviction without failing normal `malloc` calls inside `steal()`.
- **DMA base sync after boot.** `resetDma()` anchors `gDmaBaseTicks = host_virtual_ticks` so `host_audio_tx_read_frame` starts at slot 0 (matching `AudioEngine::init()`'s `i2sTXBufferPos`) and boot/preset-load ticks don't count as a spurious DMA overrun when the scheduler starts.
- **F3 (`DELUGE_HOST`) string contract.** `String::set(String const*)` (`d_string.cpp:143-149`) checks `GeneralMemoryAllocator::isNonAudioExternal(sm)` (S001) and `getAllocatedSize(sm) != 0` (S002, where `sm = alloc + 4` so `headerOf(sm)` reads the 4-byte refcount). `host_gma.cpp` returns `address != nullptr` for `isNonAudioExternal`, clamps 0-byte allocations to 4 bytes, and keeps the 4-byte header layout; `tests/platform/test_platform.cpp` covers both live `String` copying and an S002 freeze exiting 70.

### One-off `long` and LP64 audit (spec §3.3, checked at firmware `e50ff0ea5`)
Scanned all 502 compiled firmware TUs (`src/deluge`, `src/OSLikeStuff`, `src/fatfs`, `src/lib`, `src/NE10`, excluding drivers, `timers_interrupts.c`, `fault_handler/`, `general_memory_allocator.cpp`, `memory_region.cpp`) for `long`, `L`/`UL` literals, `strtol`/`to_ulong`, `sizeof`, pointer-keyed containers, and compiler `-Wformat` / `-Wsizeof-pointer-*` / pointer-cast diagnostics.

- **Compiler check:** 0 warnings across all 502 compiled firmware TUs with `-Wformat -Wformat-security -Wsizeof-pointer-memaccess -Wsizeof-pointer-div -Wint-to-pointer-cast -Wpointer-to-int-cast`.
- **252 `long` hits (excluding `long long`, `long double`, comments):**
  - 216 are `static_cast<long>` / `static_cast<unsigned long>` for `%ld`/`%lu` in `TEST_EVENT` / `event()` / `snprintf()`. Safe.
  - 15 are `long`/`unsigned long` formatting helpers/counters in `generative/firmware/` (`adapter_timing.{h,cpp}`, `compose_job.cpp`, `output_sink.cpp`, `transitions.cpp`) and `io/midi/test_port.cpp:1016-1017`. Safe.
  - 9 in `src/lib/printf.c`: adapts via `sizeof(ptrdiff_t/size_t/uintptr_t)` and 32-byte `PRINTF_NTOA_BUFFER_SIZE`. Safe.
  - 4 in `src/fatfs/ff.{h,c}`: `ff.h:61` (`typedef unsigned long DWORD`) is inactive under C99/C++23 (line 52 defines `uint32_t DWORD`); `ff.c:7018-7030` matches `va_arg(..., long)` for `%l`. Safe.
  - 5 in `src/deluge/util/functions.cpp:1647-1658` (`ConvertFromIeeeExtended`, AIFF sample rate): `UnsignedToFloat(u)` maps `[0, 2^32 - 1]` identically on LP64 and ILP32. Safe.
  - 1 in `src/deluge/storage/flash_storage.cpp:1119` (`defaultDisabledPresetScales.to_ulong()`): masks bottom 16 bits (`iterance.cpp:59`, `song.cpp:1438`, `voice.cpp:806` bitsets are all < 32 bits). Safe.
  - 2 in `src/deluge/playback/playback_handler.h:126,129` (`timeVeryFirstInputTick`, `targetedTimePerInputTick`): subtraction at `playback_handler.cpp:1901` truncates to `uint32_t`, and shifts at `:1915` are bounded by `uint32_t expectedTimeSinceVeryFirst < 2^31`. Safe.
  - 12 `L`/`UL` literals (`pack.c:231,256`, `song.cpp:3337`, `playback_handler.cpp:1911`, `functions.cpp:1647`, `sound_editor.{h,cpp}`, `patch_cables.cpp:157`, `adapter_timing.cpp`, `capture_files.cpp`, `ff.h:46`): all fit in 32 bits and convert identically.
  - 2 `iodefines` headers (`rspi_iodefine.h:54`, `ssif_iodefine.h:43,58,64,79`): `unsigned long` union members in host-RAM register structs; unused by hardware.
- **Pointer-size checks:** `MODEL_STACK_MAX_SIZE` scales with `sizeof(ModelStackWithAutoParam)`; `AlignedBuf` (`dsp/dx/aligned_buf.h:26,29`) and `DxEngine` (`dsp/dx/engine.cpp:43`) use 64-bit `size_t` alignment masks. `Kit::drumsWithRenderingActive` (`kit.h:155`) and `session.cpp`'s 32-bit pointer hash tables (`session.cpp:94,301,1663-1664`) key on the low 32 bits of pointers (full `Drum*` is stored in the element per S1); safe unless live allocations collide modulo 4 GiB.
- **Minor non-blocking findings (no firmware seam required for v1):**
  - `src/deluge/hid/led/pad_leds.cpp:82`: `unsigned long greyoutChangeStartTime` compared against `uint32_t AudioEngine::audioSampleTimer` at `:1000`. If `audioSampleTimer` wraps after ~27 h mid-fade, 64-bit subtraction underflows and snaps the LED greyout animation to done (cosmetic/LED only). Fix if desired: change to `uint32_t`.
  - `src/deluge/gui/ui/browser/browser.cpp:111`, `browser.h:197`, `storage/storage_manager.cpp:331,441`: dormant `D_PRINTLN` calls pass 32-bit `sclust` to `%lu`. Compiled out while `ENABLE_TEXT_OUTPUT` is 0; would need `static_cast<unsigned long>(...)` or `%u` if `ENABLE_TEXT_OUTPUT` is ever enabled.
