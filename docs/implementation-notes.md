# Implementation notes

Traps hit while building deluge-engine: what happened, where, and how to avoid it. The spikes' traps are in [spike-findings.md](spike-findings.md) ("Tooling problems" and the tables above it), [perform-findings.md](perform-findings.md) and [setup-findings.md](setup-findings.md).

## E1: the build

- **Compile in place works with the prefix header.** `engine/platform/host_prefix.h` is force-included first and includes the generated `RZA1/cpu_specific.h`, so the firmware's own copy, which `src/definitions.h` finds as a sibling before any `-I`, hits its include guard and is a no-op. Neither fallback (`-ivfsoverlay`, a seam) was needed. ninja's dependency log still shows the firmware's `cpu_specific.h` opened by about 420 TUs: that's the guarded no-op. `-Werror=macro-redefined` would fail the build if its body were ever read. The generated `iodefine` headers win by being first on the include path. `check.py` fails if any TU reads the firmware's own `RZA1/system/iodefine*.h`.
- **The firmware's global destructors must not run.** The Deluge never exits. At exit, `FileReader::~FileReader` frees `fileClusterBuffer`, which points `CACHE_LINE_SIZE` past the block it allocated, and malloc aborts. Host front ends end with `std::_Exit()` after flushing, as `engine/cli/render_preset.cpp` does.
- **UBSan exemptions are per file and per check** (`engine/platform/ubsan_ignorelist.txt`, passed with `-fsanitize-ignorelist`). Every other check stays on everywhere, with `-fno-sanitize-recover`. Each entry is a place where the firmware relies on what both the Deluge's Cortex-A9 and arm64 do:
  - `dsp/reverb/freeverb/freeverb.cpp`, `float-cast-overflow`: `Freeverb::update` (line 90 on) converts `INT32_MAX`-scaled floats to `int32`; `(float)INT32_MAX` is 2^31, out of range. `vcvt` and `fcvtzs` both saturate.
  - `fatfs/ff.c`, `alignment`: `ld_word` (line 617) and its siblings load through `WORD*`/`DWORD*` at any byte offset of a sector buffer. Both CPUs allow unaligned plain loads.
  - `modulation/automation/auto_param.cpp`, `alignment`: line 2097 compares an XML value's first two chars with "0x" through a `uint16_t*`.
  - `model/sample/sample_low_level_reader.cpp`, `alignment` & `pointer-overflow`: lines 1125 and 1133 (`readSamplesNative`) load 16-bit and 24-bit PCM samples through `*(int32_t*)` at 2- and 3-byte steps and mask with `bitMask`; lines 435, 690, and 875 (`bufferZeroForInterpolation`) reuse `currentPlayPos = nullptr` as a zero-sample counter (`currentPlayPos++`, checked via `(uintptr_t)currentPlayPos >= interpolationBufferSize`, never dereferenced while `clusters[0] == nullptr`).
  - Likely next, same pattern, not exempt until one fires: the other `*(uint16_t*)`/`*(uint32_t*)` compares with `charsToIntegerConstant` in `audio_file.cpp`, `note_row.cpp`, `output.cpp`, `song.cpp` and `instrument_clip_view.cpp`. Add each when it fires, with its line, here and in the ignorelist.
- **The output dither differs per channel.** A mono preset's L and R aren't sample-equal (±256 in the low bits). Compare levels, not samples.
- **`newfs_msdos` and a plain file.** It has no `-C` (create an image), so make a sparse file of the size first. macOS 27 formats the plain file given an explicit geometry: `newfs_msdos -F 32 -c 64 -S 512 -s SECTORS -h 255 -u 63 -o 0 FILE`. macOS 26 (the CI runner) refuses even with `-o 0`: "Inappropriate ioctl for device … Cannot get partition offset". There, attach the file as a raw disk with no mount, format the device, then detach: `hdiutil attach -imagekey diskimage-class=CRawDiskImage -nomount FILE` gives `/dev/diskN`; then `newfs_msdos -F 32 -c 64 -v DELUGE /dev/rdiskN` and `hdiutil detach /dev/diskN`. That route works on macOS 27 too, where `hdiutil` warns it is deprecated in favour of `diskutil image attach --noMount`, which macOS 26 may not have. The smoke test tries the plain file first and falls back to the device (`tests/smoke/test_render_pack.py`); E3's card image builder will meet the same thing. FAT32 with 32 KiB clusters needs at least 65525 clusters, so the image is at least about 2.1 GB, sparse (4 MB on disk for one preset). The firmware's `scripts/generative/fat_image.py` then writes files onto it with no mount.
- **`pack/` isn't all CC0.** `pack/LICENSES.md` has a "Derived from the factory presets" section with no CC0 claim. Tests use only presets under "Generated files" (the smoke test uses `GEN Sine Sub`).
- **cmake isn't on PATH on the build Mac.** `check.py` falls back to the firmware's dbt toolchain (`~/source/deluge-generative/toolchain/current/{cmake,ninja-build}/bin`).
- **CMake regex alternation takes the first match, not the longest.** `\.(c|cpp)` matched `foo.c` in `foo.cpp`. Put the longer alternative first.
- **The firmware needs Apple clang 21 or newer.** `util/container/enum_to_string_map.hpp:23` static_asserts on `std::size()` of a reference parameter, which only compiles with P2280 (unknown references in constant expressions). Apple clang 21.0.0 (Xcode 26.6 and 27.x) builds it. Apple clang 17.0.0 (Xcode 16.4, the macos-15 runner's default) fails in `gui/ui/ui.cpp:494`. `CMakeLists.txt` probes the construct at configure time and stops with a message naming the minimum. CI runs on the macos-26 image with Xcode 26.6 selected by path, and checks that Xcode 26.0.1's older clang trips the probe.

## E2: platform layer and the `long` audit

### Platform traps
- **`cvEngine.init()` hangs on the host.** `deluge_main()` calls `cvEngine.init()` (`processing/engines/cv_engine.cpp:63`), which calls `delayMS(10)` — a busy-wait on `*TCNT[TIMER_SYSTEM_SLOW]` in host register RAM that never ticks. `bootFirmware()` (`engine/platform/host_startup.cpp`) intentionally skips `cvEngine.init()` (as `perform_engine.cpp` did).
- **Firmware `printf.h` redefines `snprintf` as a macro.** Any host file that transitively includes `io/debug/log.h` (e.g., via `model/song/song.h`) gets `#define snprintf snprintf_` from `firmware/src/lib/printf.h`, breaking `std::snprintf`. Call unqualified `snprintf` (or include host-only helpers separately).
- **Eviction re-entrancy and sibling destruction in `host_gma.cpp`.** Calling `Stealable::steal()` can destroy other queued `Stealable` nodes in the same list (e.g., `WaveTableBandData::steal()` deletes its `WaveTable` and every sibling `WaveTableBandData`). The eviction loop unlinks the node first, runs `steal()` + `~Stealable()` + `dealloc()`, and restarts scanning the queue from `getFirst()`, marking skipped (`!mayBeStolen`) nodes with a per-pass traversal ID. A dedicated `gEvicting` guard prevents re-entrant eviction without failing normal `malloc` calls inside `steal()`.
- **DMA base sync after boot.** `resetDma()` anchors `gDmaBaseTicks = host_virtual_ticks` so `host_audio_tx_read_frame` starts at slot 0 (matching `AudioEngine::init()`'s `i2sTXBufferPos`) and boot/preset-load ticks don't count as a spurious DMA overrun when the scheduler starts.
- **F3 (`DELUGE_HOST`) string contract.** `String::set(String const*)` (`d_string.cpp:143-149`) checks `GeneralMemoryAllocator::isNonAudioExternal(sm)` (S001) and `getAllocatedSize(sm) != 0` (S002, where `sm = alloc + 4` so `headerOf(sm)` reads the 4-byte refcount). `host_gma.cpp` returns `address != nullptr` for `isNonAudioExternal`, clamps 0-byte allocations to 4 bytes, and keeps the 4-byte header layout; `tests/platform/test_platform.cpp` covers both live `String` copying and an S002 freeze exiting 70.

### One-off `long` and LP64 audit (spec §3.3, checked at firmware `e50ff0ea5`)
Scanned all 502 compiled firmware TUs (`src/deluge`, `src/OSLikeStuff`, `src/fatfs`, `src/lib`, `src/NE10`, excluding drivers, `timers_interrupts.c`, `fault_handler/`, `general_memory_allocator.cpp`, `memory_region.cpp`) for `long`, `L`/`UL` literals, `strtol`/`to_ulong`, `sizeof`, pointer-keyed containers, and compiler `-Wformat` / `-Wsizeof-pointer-*` / pointer-cast diagnostics.

- **Compiler check:** 0 warnings across all 502 compiled firmware TUs with `-Wformat -Wformat-security -Wsizeof-pointer-memaccess -Wsizeof-pointer-div -Wint-to-pointer-cast -Wpointer-to-int-cast`.

  - 15 are `long`/`unsigned long` formatting helpers/counters in `generative/firmware/` (`adapter_timing.{h,cpp}`, `compose_job.cpp`, `output_sink.cpp`, `transitions.cpp`) and `io/midi/test_port.cpp:1016-1017`. Safe.

  - 4 in `src/fatfs/ff.{h,c}`: `ff.h:61` (`typedef unsigned long DWORD`) is inactive under C99/C++23 (line 52 defines `uint32_t DWORD`); `ff.c:7018-7030` matches `va_arg(..., long)` for `%l`. Safe.

## E10: protocol, code generation, and `deluge-engine serve`

- **Protobuf 36+ `PROTOBUF_MESSAGE_GLOBALS` and Abseil `TextFormat::Printer` ABI mismatch under ASan.** Protobuf 36.2's `port_def.inc` automatically defines `PROTOBUF_MESSAGE_GLOBALS` when `ABSL_HAVE_ADDRESS_SANITIZER` is active, which alters global table layouts compared to Homebrew's prebuilt non-ASan `libprotobuf.dylib` and causes a `SIGBUS` inside `TcParser::VerifyHasBitConsistency` on the first serialize call. Defining `PROTOBUF_MESSAGE_GLOBALS_TEMPORARY_OPTOUT=1` as a `PUBLIC` compile definition on `engine_proto` fixes that while keeping every Engine TU under full ASan + UBSan. Similarly, `google::protobuf::TextFormat::Printer` embeds `absl::flat_hash_map` members whose layout differs between ASan caller TUs (running `~Printer()` inline) and non-ASan `libprotobuf.dylib` (running `Printer()` out of line); call the non-inline `google::protobuf::TextFormat::PrintToString` instead of instantiating `TextFormat::Printer` directly.
- **Keep `engine_proto` / `engine_server` decoupled from the `firmware` CMake target.** `firmware` exports `-fno-rtti`, `-ffast-math`, and `-include engine/platform/host_prefix.h` as `PUBLIC` compile options, and firmware headers redefine `snprintf` as a macro. `engine_proto` and `engine_server` do not link `firmware` so libprotobuf and `TextFormat` compile cleanly with RTTI enabled. When E12/E15 wire `engine_core`/`engine_pump` into `deluge-engine`, keep the boundary behind a plain C++ header that includes neither firmware headers nor protobuf headers.
- **Avoid `tools/proto/` colliding with top-level `proto/`.** Because `python3 -m unittest discover -t .` puts the repo root on `sys.path`, a `tools/proto/` package collides with the top-level `proto/` directory as a Python namespace package. Generated Python bindings live in `tools/proto_gen/` (`from proto_gen import engine_pb2`), and Dart bindings live in `gui/lib/proto/`.
- **Avoid naming a protobuf message `Error`.** `dart:core` exports `class Error`, so a generated Dart message named `Error` shadows `dart:core.Error` in every file that imports `engine.pb.dart`. The generic error reply is named `ErrorReply` (oneof field `error`).
- **Pinned codegen & Python protobuf environment (`proto/versions.json`).** Homebrew's `protobuf` rolls forward, so `tools/gen_proto.py` pins `protoc` (`36.2`, verified by SHA-256 download fallback if PATH differs) and `protoc_plugin` (`25.1.0`, installed into an isolated `PUB_CACHE` under `~/.cache/deluge-engine/proto/`). Because Homebrew Python is PEP 668 externally managed, `tools/proto_env.py` uses `sys.executable` when it already has the pinned `protobuf==7.36.2`, and otherwise bootstraps a cached lockfile-guarded venv under `~/.cache/deluge-engine/proto/`.

## E3: card image, sector device, read-time model, and write overlay

- **Deluge's modified `ff.c` breaks standard `f_mount(nullptr, "", 0)` unmounting.** In `firmware/src/fatfs/ff.c:3663-3666`, `f_mount` short-circuits with `if (cfs && opt == 0) return FR_OK;` without checking `fs != nullptr`. Passing `opt = 0` to unmount therefore leaves `FatFs[0]` pointing at the old `FATFS` object, causing a use-after-free/SIGSEGV on the next `f_mount` if the previous `FATFS` lived on a stack frame. Pass `f_mount(nullptr, "", 1)` to actually clear `FatFs[0]`, and keep the builder's `FATFS` at file scope (`gBuilderFatFs` in `engine/platform/card_image.cpp`).
- **Cause of the Perform spike's DMA overrun with the read-time model on.** `spike/host/host_diskio.c` never set `currentlyAccessingCard = 1` around `yieldingRoutineWithTimeoutForSD()`. During a modelled read wait (`sdRoutineLock == true`), the scheduler's `"load clusters"` task (`firmware/src/deluge/deluge.cpp:603`, registered with `RESOURCE_NONE` and guarded at runtime by `if (currentlyAccessingCard) return;` at `audio_file_manager.cpp:1273`) — as well as `RESOURCE_SD` tasks — could run inside `yieldWithTimeout()` and re-enter `disk_read_without_streaming_first()` for a 64-sector (32 KiB) cluster read. The nested call overwrote the static `cardDoneAt` and hit `yieldingRoutineWithTimeoutForSD`'s `if (sdRoutineLock)` busy-wait branch (`deluge.cpp:974-981`), spinning without running `AudioEngine::routine()` for `300 + 64 * 40 = 2860 us` against the 128-frame (`2902.5 us`) SSI TX ring, causing a DMA overrun. Holding `currentlyAccessingCard = 1` across the transfer (and freezing `E259`/`E258` on nested access, matching `firmware/src/RZA1/diskio.c:196-210, 245-256`) eliminates the re-entrant read and keeps DMA overruns at 0.
- **`disk_initialize` must not return `STA_PROTECT` when the write overlay is active.** FatFS (`ff.c:3408, 3424, 5940, 6420`) rejects writes with `FR_WRITE_PROTECTED` before calling `disk_write` if `STA_PROTECT` is set. `host_diskio.cpp` returns `0` from `disk_initialize` while keeping the underlying image file descriptor opened `O_RDONLY`, routing every `disk_write` exclusively into the process-local in-memory sector overlay.
- **Formatting and concurrency in `card_image.cpp`.** The builder formats a sparse file via `/sbin/newfs_msdos` with 32 KiB clusters (`-c 64`), automatically falling back to `hdiutil attach -imagekey diskimage-class=CRawDiskImage -nomount` + `newfs_msdos /dev/rdiskN` + `hdiutil detach` on macOS 26 when `newfs_msdos` refuses a plain file (`"Cannot get partition offset"`). `runProcess` captures stdout and stderr on separate pipes and `parseHdiutilDevice` matches only a line-leading `/dev/diskN` on stdout while refusing `/dev/disk0`. Per-entry `flock` on `build.lock` serializes concurrent builders and guards the folder scan (`scanFolder` runs inside the lock). Neither full rebuilds nor incremental refreshes ever mutate `card.img` in place: incremental refreshes copy-on-write clone `card.img` to `card.img.tmp` via macOS `clonefile()` (falling back to a full rebuild on `ENOTSUP`/`EXDEV`), update and `fsync` the clone, atomically rename it over `card.img`, and record the new inode in `manifest.tsv.tmp` -> `manifest.tsv`. Concurrent read-only readers therefore keep their old inode intact with zero tearing, and an interrupted refresh leaves both the previous `card.img` and `manifest.tsv` untouched.

## G1: Flutter GUI shell, Backend client, FakeBackend, CI

- **Flutter 3.50.1 uses `package:material_ui/material_ui.dart`.** Flutter 3.50's template depends on `material_ui: ^1.1.0` and imports `package:material_ui/material_ui.dart`. The CI workflow pins Flutter `3.50.1` (`gui/.flutter-version` and `.github/workflows/ci.yml`), matching the local SDK.
- **`FromEngine.freeze` is generated as `freeze_9` in Dart.** Because `package:protobuf`'s `GeneratedMessage` defines a `freeze()` method, `protoc-gen-dart` renames the `oneof` branch and getter to `FromEngine_Kind.freeze_9` and `msg.freeze_9` (matching protobuf field tag 9). Use `freeze_9` whenever constructing or matching `FromEngine` freeze frames in Dart.
- **Unix domain socket path length under long `$TMPDIR`.** macOS limits `sun_path` to 104 bytes, and agent/worktree `$TMPDIR` values can exceed 70 bytes. `EngineBackend.createSocketPath()` checks `< 100` UTF-8 bytes and falls back to `/tmp/de-*/e.sock` (spec §7.1); Dart Unix-socket tests should bind sockets under `/tmp` rather than `Directory.systemTemp`.
- **Headless golden fonts and 0.5% tolerance (`gui/test/golden_helper.dart`).** Call `installTolerantGoldenComparator('test/<file>.dart')` and `await loadTestFonts()` in `setUpAll`. `loadTestFonts()` loads bundled `Inter` fonts and auto-locates `MaterialIcons-Regular.otf` from `FLUTTER_ROOT` or `Platform.resolvedExecutable`, so plain `flutter test` works without setting `FLUTTER_ROOT` manually.
- **App Sandbox disabled (spec §12).** `com.apple.security.app-sandbox` is removed from both `gui/macos/Runner/DebugProfile.entitlements` and `gui/macos/Runner/Release.entitlements`, so the app can read any card folder, launch `deluge-engine`, and invoke `osascript` for the native folder picker without sandbox entitlements.
- **`tools/check.py --only gui` does not require `cmake`.** `Checker` checks for `cmake` lazily inside C++ steps so the standalone `gui` CI job runs `python3 tools/check.py --only gui` without installing C++ toolchains or checking out `firmware/`.

## E4: Engine API, preset swapping, and `deluge-engine render`

- **Exclude `firmware/src/deluge/memory/operators.cpp` on the host.** `operators.cpp` overrides global `operator new(size_t)` and `operator delete(void* [, size_t])` to call `GeneralMemoryAllocator::allocExternal` / `delugeDealloc` (which adds a 16-byte prefix before the returned pointer). That breaks both macOS libc++'s `std::stable_sort` (`operator new(n, std::nothrow)` -> system malloc, freed via overridden `operator delete(void*)`) and dynamic libraries like Homebrew's `libprotobuf.dylib` (where dyld interposes `operator new(size_t)` with GMA's `+16` pointer, while ASan routes `libprotobuf`'s `operator delete` to `libclang_rt.asan_osx_dynamic.dylib`, triggering an ASan `bad-free` in `AddDescriptors()` before `main()`). Firmware code that allocates via `GeneralMemoryAllocator` (`allocMaxSpeed`/`allocStealable` + placement `new`) must also free through the allocator rather than plain `delete`, because without `operators.cpp` plain `delete` goes to the system allocator. Firmware seam F7 (`gismya/deluge-engine#62`, `gismya/deluge-generative#569`, pinned at `1d4f3a544`) fixed the two known sites (`~ModControllableAudio()` `delete grainFX` and `AudioFileManager::removeReasonFromCluster()` `delete &cluster`) under `#if DELUGE_HOST`. Excluding `operators.cpp` alongside `general_memory_allocator.cpp` and `memory_region.cpp` keeps standard C++ `new`/`delete` on the host/ASan allocator while GMA allocations stay on `host_gma.cpp`.
- **Single-binary boundary between `engine_server` (RTTI + protobuf) and `engine_core` (`-fno-rtti` + firmware).** `engine_core_obj` compiles `engine/core/engine.cpp` with `firmware`'s private compile flags (`-fno-rtti`, `-ffast-math`, `-include host_prefix.h`), while `engine/core/engine.h` exposes a pure C++ PIMPL interface with no virtual classes and no firmware/protobuf headers. `deluge-engine` links both `engine_server` and `engine_core`, and `engine/cli/main.cpp` ends with `std::fflush(nullptr); std::_Exit(status);` after `dispatch()` destroys local RAII guards (like `serve`'s socket unlink guard) so firmware global destructors (`FileReader::~FileReader`) never run.
- **Preset swapping must clear `old->editedByUser` before `Song::replaceInstrument()`.** `Song::deleteOrAddToHibernationListOutput()` (`song.cpp:3585`) hibernates any `Instrument` with `editedByUser == true` instead of deleting it. Clearing `old->editedByUser = false`, calling `midiFollow.removeClip(clip)` and `actionLogger.deleteAllLogs()`, and sweeping unreferenced `AudioFile` entries (`numReasonsToBeLoaded == 0`) after `replaceInstrument()` keeps repeated Synth/Kit swaps clean under ASan.
- **Host `TestPort` sink via `MIDICable` subclass.** Installing a `HostTestCable` on `Debug::midiDebugCable` and passing it to `TestPort::injectReceived()` captures both synchronous status replies (`02 50 <seq> <status>`) and `TestPort::event()` lines (`03 40 01 <ascii>`) directly without consuming DIN UART TX buffer space.
